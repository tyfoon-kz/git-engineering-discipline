# Локальные слои Git

Главная схема локальной модели:

```text
working tree -> staging area -> repository -> HEAD
```

`working tree` - это текущие файлы проекта, которые я редактирую в терминале или IDE. После изменения файла правка сначала находится именно здесь. Ее можно увидеть через `git status` и обычный `git diff`.

`staging area` - это подготовленная область будущего commit. Когда я выполняю `git add README.md`, Git помещает выбранную версию файла в index. Это еще не commit, а только сборка будущего commit.

`repository` - это сохраненная история Git. После `git commit` подготовленное состояние становится частью истории, и его можно показать через `git log` или `git show HEAD`.

`HEAD` - это текущая позиция Git в истории. В обычной ситуации он указывает через текущую ветку на последний commit этой ветки. Git использует `HEAD` как точку сравнения для status, diff и show.

Пример движения изменения:

```text
1. Я изменил README.md.
   Изменение находится в working tree.

2. Я выполнил git add README.md.
   Выбранная версия файла находится в staging area.

3. Я выполнил git commit -m "Update README".
   Изменение сохранено в repository history, а HEAD указывает на новый commit.
```

После `git add` обычный `git diff` может стать пустым, потому что незастейдженных изменений больше нет. Чтобы увидеть подготовленное изменение, нужно выполнить `git diff --staged`. Поэтому перед commit важно понимать, на какой слой смотрит команда.

Перед сохранением работы я использую `make status`, `make diff` и `make check`, чтобы проверить локальное состояние через команды проекта.
