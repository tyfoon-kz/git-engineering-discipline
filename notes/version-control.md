# Зачем проекту нужна история версий

Копия папки кажется безопасной, пока проект маленький. Можно сделать `project-final`, потом `project-final2`, потом `project-final-after-fix`, но через несколько дней эти имена перестают отвечать на главные вопросы. Непонятно, какие строки изменились, почему изменение появилось, кто его сделал и можно ли доверять этому состоянию.

Git решает не проблему красивых имен папок, а проблему проверяемой истории. Commit сохраняет состояние проекта, связывает его с предыдущим состоянием и добавляет сообщение автора. Поэтому версию можно сравнить, показать другому человеку и использовать в review.

```text
Папки-копии:
project-final/
project-final2/
project-final-after-fix/

Вопрос остается открытым: что именно изменилось?

История Git:
commit A -> commit B -> commit C

Ответ можно получить через diff и сообщение commit.
```

Нормальная версия должна отвечать на четыре вопроса:

1. Что изменилось в файлах.
2. Зачем это изменение было сделано.
3. Когда оно появилось.
4. Кто его сохранил в историю.

Перед сохранением версии я проверяю состояние проекта через `make status`, смотрю diff через `make diff` и запускаю базовую проверку через `make check`. Это продолжает привычку из Module 00: повторяемые действия должны жить в проекте, а не только в памяти разработчика.
