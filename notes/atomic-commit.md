# Atomic Commit

Атомарный commit сохраняет одну законченную инженерную мысль. Он может изменить несколько файлов, если все они нужны для одной причины. Например, `Makefile` и `README.md` могут попасть в один commit, когда оба файла объясняют workflow `make check`.

Плохой смешанный commit выглядит так: в одной истории лежат заметка о Git, временный debug-файл и случайная правка стилей. Reviewer не понимает, какую задачу проверять, а откатить только одну часть становится сложнее.

Перед commit я проверяю:

```bash
make status
make diff
make check
```

Если будущий commit нельзя назвать одной понятной фразой, изменение нужно разделить до сохранения истории.
